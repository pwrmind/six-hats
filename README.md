# 🎩 Six Hats Skills

Набор из 6 навыков (`SKILL.md`) для ИИ-ассистентов GigaCode, VS Code, JetBrains IDE и других Agent Skills-совместимых сред.

Реализует метод шести шляп мышления Эдварда де Боно для анализа идей, фич, архитектуры, рисков и UX.

## Состав

| Навык | Роль | Назначение |
|---|---|---|
| `blue-hat` | Оркестратор | Управляет дискуссией, сводит итог |
| `white-hat` | Факты | Данные, метрики, ограничения, стандарты |
| `yellow-hat` | Выгоды | Ценность, плюсы, лучший сценарий |
| `black-hat` | Критика | Риски, уязвимости, edge cases, техдолг |
| `green-hat` | Креатив | Альтернативы, нестандартные решения |
| `red-hat` | Эмоции | UX, страхи, восторги, человеческий фактор |

## Использование

### Сценарий: оценка идеи перед стартом спринта

Команда обсуждает фичу — **авторизация по FaceID в веб-приложении**. Мнения разделились: продакт хочет быстрый вход, безопасник против биометрии, фронтендер сомневается в поддержке браузеров. Нужно взвешенное решение.

#### Запрос в GigaCode

Откройте чат и вызовите главный навык:

```text
@blue-hat оцени идею: добавить авторизацию по FaceID в веб-приложение.
Контекст: B2C-продукт, 500k MAU, стек — React + Node.js, регуляторика РФ.
Цель: сократить время входа и повысить конверсию регистрации.
```

#### Ответ GigaCode

```markdown
### 📑 Анализ задачи методом «6 шляп»

⚪ white-hat:
- WebAuthn API поддерживается в 92% современных браузеров.
- Требуется HTTPS и защищённый контекст (secure context).
- По ФЗ-152 биометрия — специальная категория ПДн, нужно согласие.
- Статистика: 98% успешных срабатываний FaceID на iOS Safari.
- 8% пользователей — устройства без камеры или с ограничениями.

🟡 yellow-hat:
- Вход за 1–2 секунды вместо 15–20 секунд с паролем.
- Рост конверсии регистрации на 10–15% (по кейсам конкурентов).
- Снижение нагрузки на поддержку по «забыл пароль» на 30%.
- Сильный маркетинговый фич-поинт: «вход без пароля».

⚫ black-hat:
- Регуляторный риск: биометрия в РФ требует отдельных согласий и хранения.
- При отказе камеры или старом устройстве — блокировка входа.
- Фишинг и подмена origin — критичный вектор атаки на WebAuthn.
- Нет fallback → часть пользователей потеряет доступ.
- Транспорт данных биометрии нельзя логировать, усложняется отладка.

🟢 green-hat:
- FaceID как опция, пин-код как fallback — гибридная схема.
- Одноразовый QR-код через мобильное приложение вместо биометрии на веб.
- Локальная проверка биометрии на устройстве без передачи на сервер.
- Геймификация: «включи FaceID — получи месяц Premium бесплатно».

🔴 red-hat:
- Пользователи пугаются запроса доступа к камере на сайте.
- Молодые tech-savvy пользователи в восторге от инновации.
- Команда безопасности будет насторожена и потребует аудит.
- Поддержка опасается роста обращений от тех, у кого не работает.

### 🔵 Синтез blue-hat

- **Рекомендуемое решение:** FaceID как опциональный метод входа
  на устройствах с поддержкой WebAuthn. Fallback — пин-код + SMS.
- **Компромиссы:** Не для 100% пользователей, но покрывает 90%+ активной
  аудитории. Регуляторику закрываем через явное согласие и хранение
  биометрии только на устройстве пользователя.
- **Ключевые риски и меры:**
  - Регуляторный → согласование с юристами и DPO до старта.
  - Безопасность → пентест WebAuthn-флоу.
  - UX → плавный онбординг и понятные объяснения.
- **Что проверить до старта:**
  - Поддержку WebAuthn на топ-10 устройствах аудитории.
  - Стоимость и сроки юридического согласования.
  - Метрику baseline: текущее время входа и конверсия.
- **Следующие шаги:**
  1. Собрать данные по устройствам пользователей.
  2. Юридическая оценка ФЗ-152.
  3. Прототип на 1% трафика с A/B-тестом.
  4. Решение о полном раскате по результатам эксперимента.
```

#### Что произошло

1. `blue-hat` последовательно применил пять ролей.
2. Каждая шляпа дала вклад строго в своей логике.
3. Итоговый синтез свёл мнения в конкретный план действий.
4. Команда получила не «одно мнение», а **карту решений и рисков**.

### Другие сценарии

#### Только критика

Если нужно быстро оценить риски:

```text
@black-hat проанализируй: переход с монолита на микросервисы
```

#### Только креатив

Если застряли и нужны альтернативы:

```text
@green-hat предложи альтернативы: как ускорить онбординг новых разработчиков
```

#### Только UX и эмоции

Если нужно понять реакцию пользователей:

```text
@red-hat оцени: обязательная двухфакторная аутентификация для всех
```

#### Полный консилиум с фокусом

```text
@blue-hat оцени идею: внедрить оплату по подписке.
Фокус: риски и альтернативы. Контекст: B2B SaaS, 200 клиентов.
```

### Рекомендации по промптам

| Что хотите | Как формулировать |
|---|---|
| Полный анализ | `@blue-hat оцени идею: ...` + контекст |
| Быстрые риски | `@black-hat проанализируй: ...` |
| Нужны варианты | `@green-hat предложи альтернативы: ...` |
| UX-реакция | `@red-hat оцени: ...` |
| Только факты | `@white-hat собери данные по: ...` |
| Только выгоды | `@yellow-hat найди плюсы в: ...` |

**Совет:** чем больше контекста дадите (стек, аудитория, ограничения, метрики), тем точнее будет синтез. `blue-hat` при нехватке данных сначала запросит факты через `white-hat`.

## Как это работает внутри

`blue-hat` — точка входа. При получении задачи он:

1. Фиксирует контекст и критерии успеха.
2. Последовательно применяет роли `white-hat`, `yellow-hat`, `black-hat`, `green-hat`, `red-hat`.
3. Если платформа поддерживает вызов скиллов из скиллов — обращается к ним напрямую.
4. Если нет — моделирует их ответы внутри одного ответа.
5. Сводит мнения в итоговый синтез с планом действий.
